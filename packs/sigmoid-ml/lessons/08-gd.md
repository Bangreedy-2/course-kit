## Why this matters

Gradient descent is how almost every machine learning model learns: logistic regression in week 4, the SVM in week 7, every neural network you will ever train. The handbook implements linear regression with it, and homework 3 asks you to train that implementation and compare it with scikit-learn. If your from-scratch R² comes out far below sklearn's, the cause is nearly always the learning rate, the number of iterations or unscaled features. This lesson gives you the understanding to fix that.

## The idea: walk downhill

The cost f(w) is a surface over all possible weight vectors. With two weights (slope and intercept) you can picture it as a bowl: every point on the floor is a choice of (w, b), and the height is the cost. Training means finding the bottom of the bowl.

You cannot see the whole bowl, but at any point you can compute the **gradient**, written ∇f (the symbol ∇ is "nabla"). The gradient is the vector of partial derivatives, one per weight: ∂f/∂wⱼ says how fast the cost rises if you nudge weight j up a little while holding the others fixed. The gradient points in the direction of steepest *increase*. So step the other way:

$$
w ← w − α · ∇f(w)
$$

**α** (alpha) is the **learning rate**, the size of the step. Repeat until the cost stops falling. That is the whole algorithm. The handbook compares it to a ball rolling down a hill.

## The gradient of the squared-error cost

For f(w) = (Xw − y)ᵀ(Xw − y), the handbook gives the gradient without deriving it:

$$
∇f = 2Xᵀ(Xw − y)
$$

You can see why it has this form without calculus beyond one rule. The cost is Σᵢ eᵢ², where eᵢ = ŷᵢ − yᵢ. The derivative of eᵢ² with respect to wⱼ is 2eᵢ times how much eᵢ changes when wⱼ changes, and since ŷᵢ = Σⱼ wⱼ x_ij, that change is x_ij. So ∂f/∂wⱼ = Σᵢ 2 eᵢ x_ij. Writing that for every j at once is exactly 2Xᵀe. Shapes: Xᵀ is (d, n), e is (n, 1), the gradient is (d, 1), the same shape as w.

For the **mean** squared error, divide by n: ∇MSE = (2/n) Xᵀ(Xw − y). With one feature and an intercept, written out:

$$
dw = (2/n) · Σ (ŷᵢ − yᵢ) · xᵢ
db = (2/n) · Σ (ŷᵢ − yᵢ)
$$

The intercept's "feature" is the column of ones, so its gradient is just the sum of errors.

## A worked step

Points (1, 1), (2, 2), (3, 2); start at w = 0, b = 0; learning rate α = 0.1.

1. Predictions are all 0, so errors ŷ − y are −1, −2, −2.
2. dw = (2/3)·((−1)(1) + (−2)(2) + (−2)(3)) = (2/3)(−11) ≈ −7.333. db = (2/3)(−5) ≈ −3.333.
3. Update: w = 0 − 0.1·(−7.333) = 0.7333; b = 0 − 0.1·(−3.333) = 0.3333.

Both gradients were negative (raising w or b lowers the cost), so both weights went up. The MSE drops from 3.0 to about 0.110 in one step. After step 2 it is about 0.074, after step 3 about 0.073; it keeps creeping toward the minimum 0.0556 at w = 0.5, b = 0.667. Steps shrink automatically as the gradient flattens near the bottom, even though α stays fixed.

## The learning rate

- **Too small** (α = 0.01 here): every step is tiny. After 50 steps the cost is still 0.0714, well above the minimum. Training "works" but needs many more iterations.
- **Too large** (α = 0.3 here): each step overshoots the bottom and lands higher on the other side. The cost explodes; after 50 steps the weights are around 10¹⁸. If your from-scratch model outputs `nan` or enormous numbers, the learning rate is too large.
- **Right**: the cost falls fast at first and then levels off.

The practical method is the one the handbook describes: try several values (0.1, 0.01, 0.001, …), plot the cost against the iteration number for each, and pick the largest α whose curve falls smoothly. A cost curve is the single most useful debugging plot for gradient descent.

Why does the handbook's code use a learning rate as small as 0.00001? Its update is `w -= learning_rate * Xᵀ(Xw − y)`: there is no division by n, so the gradient grows with the batch size and with the size of the feature values. Large raw values (house areas in the hundreds, prices in the hundreds of thousands) make the gradient huge, and only a tiny α keeps the steps stable.

## Feature scaling makes gradient descent fast

When one feature ranges over 0 to 1 and another over 0 to 1,000, the bowl becomes a long narrow valley. A learning rate small enough for the steep direction is far too small for the flat one, and the path zig-zags slowly along the valley floor. **Standardising** each feature to mean 0 and standard deviation 1 (`StandardScaler`, week 9) makes the bowl round and lets one learning rate work for all weights. For homework 3, scale X before training the from-scratch model; you will typically get much closer to sklearn's R² with far fewer iterations. sklearn's `LinearRegression` does not need scaling because it solves the problem directly.

## Batch, mini-batch and stochastic

How many rows go into each gradient?

- **Batch** (full-batch) gradient descent: all n rows per step. Smooth, exact gradient, one step per pass over the data.
- **Stochastic** gradient descent (SGD): one row per step. Very noisy, but many cheap steps.
- **Mini-batch**: a small group of rows (16, 32, 64) per step. The usual compromise, and what the handbook implements with `batch_size=16`.

One full pass over the training data is called an **epoch**. With 354 training rows and batch size 16, one epoch is ⌈354/16⌉ = 23 updates (⌈ ⌉ means round up, `math.ceil`), so 500 iterations perform 11,500 updates. The data is **shuffled** at the start of each epoch so batches differ every time; otherwise the same rows would always be grouped together and the path would repeat its biases.

## The handbook's implementation, line by line

```
def gradientDescent(self, X, y, learning_rate=0.00001, iterations=500, batch_size=16):
    X = np.concatenate([X, np.ones_like(y)], axis=1)   # 1
    rows, cols = X.shape
    X = np.append(X, y, axis=1)                         # 2
    w = np.random.random((cols, 1))                     # 3
    for i in range(iterations):                         # 4
        np.random.shuffle(X)                            # 5
        y_it = X[:, -1].reshape((rows, 1))              # 6
        X_it = X[:, :-1]
        for batch in range(math.ceil(rows / batch_size)):            # 7
            batch_start = batch * batch_size
            x_batch = X_it[batch_start : min(batch_start + batch_size, X.shape[0])]
            y_batch = y_it[batch_start : min(batch_start + batch_size, X.shape[0])]
            w -= learning_rate * np.matmul(x_batch.transpose(),
                                           (np.matmul(x_batch, w) - y_batch))  # 8
    self.params__ = w
    return self
```

1. Add the column of ones for the intercept. `np.ones_like(y)` makes ones with y's shape, so y must be a column of shape (n, 1) for the concatenation along `axis=1` to work.
2. Glue y onto X as the last column, so a single shuffle keeps each row's features and target together.
3. Random starting weights between 0 and 1, shape (cols, 1).
4. Each outer iteration is one epoch.
5. Shuffle the rows in place.
6. Split back: the last column is y, everything else is X. `[:, -1]` means all rows, last column; `[:, :-1]` means all rows, every column except the last.
7. Walk through the batches. `min(...)` stops the last batch at the end of the data when n is not a multiple of 16.
8. The update: Xᵀ(Xw − y) for the batch, times the learning rate. This is the gradient without the factor 2 (absorbed into α) and without dividing by the batch size.

`predict` adds the same column of ones and returns `X @ w`. Two quirks to know for homework 3: `y` must be passed as a column (`y.reshape(-1, 1)`), and with unscaled features you need the tiny default learning rate or a scaled X.

## When to stop

Fixed iteration counts are simplest. Better options: stop when the cost improves by less than a small tolerance between epochs, or when the cost on a held-out **validation** set starts to rise (that is the start of overfitting, week 7). sklearn's `SGDRegressor` exposes these as `tol` and `early_stopping`.

## Common mistakes

> **Updating w before computing the gradient for b** (or updating weights one by one using already-updated values). Compute the whole gradient with the current weights, then update all weights together.

> **Forgetting to shuffle with mini-batches**, or shuffling X and y separately, which scrambles the pairing. The handbook's `np.append` trick prevents this.

> **Judging a run by its last cost only.** Plot the curve. A flat curve from the start means α is too small; a rising curve means too large.

## Summary

Gradient descent repeats w ← w − α∇f(w). For squared error, ∇f = 2Xᵀ(Xw − y); for MSE divide by n. The learning rate decides everything: too small is slow, too large diverges. Scale features so one α suits every weight. Mini-batches trade gradient accuracy for many cheap updates; one epoch is one pass over the data; shuffle each epoch. The handbook's class adds a ones column, shuffles X and y together, and updates per batch with `Xᵀ(Xw − y)`.

```solution
def gradient(X, y, w):
    n = len(X)
    errs = [sum(a * b for a, b in zip(row, w)) - t for row, t in zip(X, y)]
    return [2 / n * sum(e * row[j] for e, row in zip(errs, X)) for j in range(len(w))]

def gd_step(X, y, w, lr):
    g = gradient(X, y, w)
    return [round(wj - lr * gj, 4) for wj, gj in zip(w, g)]

def train(X, y, lr, steps):
    w = [0.0] * len(X[0])
    for _ in range(steps):
        g = gradient(X, y, w)
        w = [wj - lr * gj for wj, gj in zip(w, g)]
    return [round(v, 4) for v in w]
```
! After enough steps gradient descent lands on the least-squares answer (0.5, 0.6667) you found with the closed form in the previous lesson.
